============================================================
1. PRODUCT IDENTITY
============================================================

App Name:
PrimeContractorOS

Purpose:
PrimeContractorOS is a guided government-contracting operating system for prime contractors, subcontractors, business owners, and platform administrators.

The app helps users move through the full government-contracting lifecycle:

Public Entry
→ Signup
→ Workspace Creation
→ Onboarding
→ Dashboard
→ Opportunities
→ Proposals
→ Awarded Contracts
→ Contract Hub
→ AI Confirmation
→ Files / Contacts / Messages
→ Invoices / Payments / Finance
→ Reports / Capability Statements / Templates
→ Closeout
→ Lessons Learned
→ Platform-Owner Administration

PrimeContractorOS is not:
- a generic CRM
- a generic project manager
- a file storage app
- a basic accounting dashboard
- a static landing page
- a chatbot-only app
- a disconnected group of pages

It is a connected operating system for government contracting operations.

============================================================
2. CORE PRODUCT STANDARD
============================================================

The finished app must feel like a serious operating system for government contracting.

It must help users:
- understand where they are in the contracting lifecycle
- know what matters now
- know what is missing
- know what needs action
- keep files, contacts, messages, invoices, payments, proposals, contracts, tasks, alerts, and AI findings connected
- manage awarded contracts from source files
- separate invoices from payments
- use AI safely and review-first
- close contracts carefully
- learn from losses and closeouts
- let the platform owner run the software business separately from customer operations

Do not simplify the app.

Build the full connected system.

10. WORKSPACE-FIRST ARCHITECTURE
============================================================

Everything customer-side must belong to a workspace.

Every customer-side record must include workspace_id.

A user may only see data inside workspaces they belong to.

Customer workspaces must be fully separated from each other.

Platform-owner/admin users may see workspace summaries from /platform, but ordinary customer users must never see another customer’s workspace data.

============================================================

Build real role-based permissions.

- Owner Admin
- Trusted Admin
- Standard User
- Specialized User
- Read Only

Platform roles:

- Platform Admin
- Platform Support
- Platform Billing/Admin Recovery if needed later

Permission rules:

Owner Admin can:
- manage workspace settings
- manage users
- manage business profile
- create/edit/archive records
- approve AI findings
- manage contracts, invoices, files, contacts, messages, tasks, and alerts
- view subscription summary

Trusted Admin can:
- help manage operations based on assigned permissions

Standard User can:
- create/edit assigned operational records where allowed

Specialized User can:
- work in narrower areas such as finance, proposals, or contract management depending on permissions

Read Only can:
- view allowed records
- not edit
- not delete/archive
- not approve AI findings
- not change billing/access
- not manage users

Platform Owner can:
- access /platform
- manage workspaces
- manage plans
- manage discounts
- manage billing/access states
- use owner overrides
- view support inbox
- view workspace summaries
- manage platform tasks

Platform Owner should not casually edit customer operational records from the platform pages.

AI must respect permissions. AI cannot let a user do something their role does not allow.
